# 全 ARM 电机驱动软件架构说明

## 1. 架构目标

该架构将原方案中 ARM 与 FPGA 的软件功能收敛到单 ARM MCU/SoC：ARM 同时承担通信协议、编码器协议、实时采样、三环控制、PWM 调制、故障处理以及电机辨识。

两个核心产品能力为：

1. 电机类型自动识别：通过受控激励、响应采集、特征提取、候选模型判别和置信度评估，自动选择后续控制模型与初始参数集。
2. 电机参数在线辨识：在闭环运行过程中估计或跟踪 Rs、Ld/Lq、磁链、转动惯量、阻尼和负载扰动，并对参数更新进行质量门控、限幅、滤波、无扰切换和异常回滚。

## 2. 从原方案保留的接口和能力

- CAN/CANopen、RS232、PWM 指令、数字输入输出。
- 增量式编码器、霍尔、SSI、BiSS-C、EnDat 和绝对值编码器接口。
- 三相电流、母线电压、温度和模拟指令采样。
- 位置环、速度环、电流环、FOC/SVPWM、历史故障存储。
- 双通道 STO、过流、过压、过温、超速、编码器和通信故障保护。

## 3. 关键设计边界

- “全 ARM”是控制与协议处理架构，不代表把 STO 等安全功能软件化。STO 和快速过流必须保留独立硬件关断路径，ARM 只负责状态监测、诊断和故障记录。
- BiSS-C/EnDat 等协议原来由 FPGA 处理。改为 ARM 后，选型阶段必须验证高级定时器、SPI、输入捕获、DMA、CRC、GPIO 翻转时序和最坏中断延迟；若目标 ARM 外设不足，不能仅靠提高主频弥补确定性问题。
- 电机类型不是无限集合。PMSM（SPM/IPM）、BLDC、IM 等候选类型应按功率级拓扑、传感器配置和产品定义裁剪，并为每类模型建立可验证的判别特征。
- Rs、Ld/Lq、磁链、J、B 可在合适工况下在线跟踪；极对数、相序和编码器零位通常需要停机或专用调试激励，不宜在正常带载运行中持续更新。

## 4. 建议的时间域划分

| 时间域 | 典型频率 | 主要内容 |
|---|---:|---|
| PWM 快中断 | 10–40 kHz | ADC 同步采样、电流环、角度更新、SVPWM、快速保护 |
| 中速任务 | 0.1–2 kHz | 速度环、在线参数辨识、观测器、温升和负载估算 |
| 慢速任务 | 10–100 Hz | 位置环、状态机、诊断、参数质量判断和持久化调度 |
| 后台任务 | 事件驱动 | CANopen、RS232、日志、升级、非易失存储 |

具体频率必须根据目标 ARM、PWM 频率、编码器协议和最坏执行时间实测确定。

## 5. 辨识结果的使用原则

辨识器不能直接无约束地改写控制参数。推荐的数据链为：原始估计值 → 可观测性/残差检查 → 置信度 → 物理边界检查 → 变化率限制 → 滤波 → 控制器无扰更新。若新参数导致电流、速度或残差异常，应立即回滚到上一个已验证参数集。
